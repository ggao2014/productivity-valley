# v0.9 封闭测试计划

## 目标与边界

本轮验证两件事：

1. 完成现实待办是否会促使玩家回来；
2. NPC 与山谷成长是否比普通待办应用更有吸引力。

邀请制仅用于控制测试样本，不承担账号或安全验证。默认邀请码为 `SHANGU-09`，部署时可用 `VITE_BETA_CODE` 替换。已有本机存档的玩家自动通行。

## 数据原则

- 匿名产品事件默认关闭，必须由玩家主动打开。
- 第 1/7 日从玩家主动打开匿名记录的时刻开始计算，而不是从浏览邀请页开始。
- 事件只保存在玩家当前设备。
- 关闭开关会立即清空本机事件。
- 不记录待办标题、对话内容、反馈正文、姓名、邮箱、设备标识或网络地址。
- 玩家可随时检查并导出事件 JSON。
- 反馈不会自动发送，只下载到玩家设备；玩家检查后自行决定是否分享。

## 事件口径

| 事件 | 触发 |
|---|---|
| `first_task_completed` | 首次完成待办 |
| `core_loop_completed` | 已完成待办后，首次与角色进行核心互动 |
| `friendship_stage_unlocked` | 首次记录某角色的某个友情阶段 |
| `romance_stage_unlocked` | 首次记录某角色的某个爱情阶段 |
| `room_purchased` | 成功购买房间 |
| `return_day_1` | 首次在安装日之后至少 1 个自然日回来 |
| `return_day_7` | 首次在安装日之后至少 7 个自然日回来 |

## 测试节奏

1. 邀请 10–20 名愿意连续使用两周的测试者。
2. 第一次使用后不要求每天签到，只请测试者按真实需要使用。
3. 第 7 天与第 14 天提醒一次：打开“测试反馈”，导出并自行分享 JSON。
4. 将收到的 JSON 放入同一目录后运行：

```bash
npm run beta:summary -- path/to/feedback-directory
```

## 决策门

- 首次核心循环完成率 ≥ 70%
- 次日返回率 ≥ 35%
- 能正确描述核心经济关系 ≥ 60%
- 能说出至少一名记得住的角色 ≥ 50%
- 严重存档丢失 = 0

脚本只汇总已收到的反馈文件，不推断未提交者行为。若样本过少或回收偏差明显，结果不得用于进入 1.0 的决定。
